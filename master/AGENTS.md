# master：进程内多 Agent 指挥官

指挥官与 Worker 的提示词在 `prompts/`，工具描述与续跑提示在 `messages.ts`。这里只记代码里看不出的取舍。

- Worker 是主进程内的 SDK 子会话，不是独立进程：reload 会中断在飞回合（会话记录与审查义务保留，可续派），换来父进程退出即全停、无幽灵进程、无跨进程对账。多个 Worker 可并行写同一 checkout，没有写租约，集成与验证归指挥官。
- 档案新增可选字段不升版本，旧档缺它照常读。fork 出的会话带着 pending 事件却没有档案，重投时可能提到不在池里的 Worker：已知边缘，接受。
- 释放计时只在 Master 落定一次运行时起，池不按会话事件自判：审查期间 Worker 自己的会话是闲的，修复回合也会落定，按事件判会在审查中误释放。
- 子会话的 `steer` 是它自己的消息队列，不走根 AGENTS.md 的 `deliver.ts` 规则，也不会唤起歇透的会话。
- `start` 开不成与回合失败同样落定为失败：票以 idle 留在池里，由指挥官 `send` 重试或 `kill`，不自动撤票。暂停后到点的自动续跑一经写档进 working/reviewing 就是在跑的运行：要停用 `interrupt`，不另设取消意图。
- `review:true` 不在落定时自动开审：模型停下可能是在提问或交半成品，落定不等于完成。义务不灭归代码，送审时机归指挥官。
- `bash` 是可信能力（开放它是为了让 Worker 自跑测试），edit/write 守卫只防误伤。
