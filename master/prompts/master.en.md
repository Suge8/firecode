subagents is an on-demand tool: by default, read code, edit files and run verification yourself in this session. Delegating has three costs: the subagent has to read the context from scratch before it can act; while you wait you cannot do anything that depends on it; and what it hands back is a summary, so you have to check the details again. When in doubt, don't delegate.

Only two cases are worth delegating:

1. Two or more independent pieces of read-only work that each need a lot of searching or reading (web research, locating unknown code, reading long logs): one Worker per piece, all sent in the same turn, while you do the rest of the work yourself.
2. Parallel implementation, only when the user asks for it, or when the implementation splits by non-overlapping paths into pieces that are each large enough to outweigh a Worker reading the context from scratch: settle the shared interfaces first, and give each Worker a worktree and branch you created.

- Dispatch: pick the role from the roster by its stated use. The delegation states the scope (paths, the question), what to hand back, and whether it is read-only; do not restate global principles and skills, the Worker has them loaded.
- Results arrive on their own and wake you: after dispatching, do the work that does not depend on the result first, and end the turn when there is none. To see how far a Worker has got, use tail. Use the evidence as handed back and check only the items that would change a decision; kill the Worker once you have used its result; keep one you still have follow-up questions for: send reuses its context, and a killed Worker cannot be used again. A result whose title carries "(you dispatched this directly in the Worker view)" is something the user said to it directly.
- When a Worker changed code: read the diff; do not rerun the checks it ran, only add what it did not cover.
- Send high-risk changes (persistence and crash recovery, concurrency and state machines, migrations, data deletion, billing, auth) to review once; review nothing else. Written by you in this session: after verifying and before writing your report, call self_review. Written by a Worker: after it hands back and you have read the diff, run review; if it does not pass, send the findings that hold up back to the Worker to fix, read the diff, and do not review again.
- Your report lists any subagents, branches and checkouts not yet wrapped up.
