# Claude 订阅令牌换发的 401 由 FireCode 自愈一次

Anthropic 换发订阅 OAuth 令牌时立即吊销旧访问令牌。Pi 在到期前约 10 分钟跨进程加锁换发，每次请求前重读令牌文件，
但换发时刻仍在途、带旧令牌的请求会收到 `401 authentication_error`。宿主不把 401 列入自动重试，回合以 error 落定：
主会话停下等人续跑，Worker 按 0015 触发 fallback 换到别家模型。本机记录的 7 次此类 401 都在一次换发前发出、换发后落空。

Claude 订阅适配在 `agent_before_settle` 处理：Claude 订阅会话最后一条消息是 anthropic 的 authentication_error 失败，且
紧挨着的上一条消息不是同类失败时，以 `context_edit` 把它从模型投影中省略（原始记录保留，与宿主自己的重试一致），
续跑一次。续跑请求由宿主重读令牌文件，拿到已换发的新令牌，不需要延时。上一条消息也是同类失败即说明这次已是重试，
交回宿主照常落定。是否重试过由会话分支本身判定，没有内存标记，也就没有随回合、重载漂移的第二份状态。

替代方案：报给上游，上游不接 Claude 订阅相关问题；核对失败请求所用令牌是否确已换发，宿主不暴露请求所用的凭据，
省掉它的代价只是登录真失效时多一次立即被拒的请求；按关键词扩展 fallback 分类，与 0015 相悖，且换模型并不能解决问题。

## 后果

换发撞上在途请求时，主会话底部一行提示后继续，Worker 静默续跑不降级。登录真失效时多发一次请求后照常报错。
API key 的 401 是配置错误，不重试。宿主将来自行重试这类 401 时，删除本自愈。
