# 角色表即角色词汇

`master.roles` 的键就是角色名，任意非空字符串均可；代码不再持有固定角色词汇表。`subagents` 工具的 role 参数枚举在注册时由角色表生成，宿主按 schema 校验参数，因此指挥官不可能派出未配置的角色，派发代码只做查表。指挥官提示词只保留通用派发纪律，角色的适用场景全部由配置的 `use` 字段经动态角色表进入提示词，静态文本不再点名任何角色。

替代方案是保留六词固定词汇并让配置启用子集。该方案让同一组角色名同时存在于代码常量、工具枚举、配置校验、测试与三处文档，而真正决定可派角色的只有配置；每次增减角色都要同步全部副本，并保留一条实际不可达的「角色未配置」运行时分支。

## 后果

角色名只在配置一处出现，增减角色改配置重启即生效。代价是角色名拼写错误不再在配置加载时报告——它已无对照物；角色表激活时随系统提示打印，可直接核对。ADR 0012 的 fallback 规则不受影响。
