# tools：过程组与过程列表

| 文件 | 职责 |
| --- | --- |
| `index.ts` | 包装默认四工具的展示与执行耗时；TUI 会话安装分组，退出释放 |
| `grouping.ts` | 宿主适配：定位聊天容器，安装渲染/鼠标投影，分离全局展示与单工具正文 |
| `group-view.ts` | 从原组件顺序派生过程组、组摘要与过程列表 |
| `assistant-view.ts` | 思考/正文投影，封装宿主助手组件的内部结构，不重建 Markdown |
| `line.ts` `parts.ts` | 单工具行、组摘要、正文及着色片段；Master 复用纯渲染部分 |
| `timing.ts` | 真实工具执行耗时，结果渲染取走即释放 |

改分组前核对宿主 `ToolExecutionComponent`、`AssistantMessageComponent`、`Container` 和 TUI 动态引用。
原消息与聊天树不改写、不搬移；渲染与鼠标命中使用同一投影。两档展示直接读取 `getToolsExpanded()`，
不拦截快捷键。过程列表保留原生思考组件与其展开设置；单工具正文仍由宿主工具行持有，其他卡片保持原生行为。

过程节点是三类宿主组件：助手消息、工具行、CustomMessage（模型收件），加上段内出现的整行单色 `Text`——
宿主把 transcript 提示画成 warning、状态行画成 dim，颜色是它唯一给出的语义通道（只折入有工具或思考的段，连同前导
Spacer，warning 计入 `⚠ N`；无摘要行可依附时保持原样，避免为提示凭空造摘要行顶开回复）；错误、混色文本与其余节点（用户消息、CustomEntry 等）是段边界。段尾回复是其后只剩提示的
最后一条助手消息。段尾若是带正文或诊断的助手消息则作为回复显示，其余整段折成一行摘要；渲染器有没有
图片、鼠标处理都不影响入组——折叠态不画正文，展开态正文与点击归宿主行和渲染器自己。

单行渲染器通过 `renderGroup(width, summary)` 只复用自身动作词，不露目标与元信息，不把最后一个工具的耗时冒充
整组耗时。摘要行不铺工具背景色，运行中用 `✦`；失败数是固定尾巴，按标签计数是右列且整列去留，
`renderLine` 的布局规则对工具行与摘要行只有一份。按能力而非类身份选择，避免扩展多次加载产生的 ToolLine 副本不相等；未提供该能力的静态
工具使用通用参数摘要。单工具详情的鼠标事件按裁掉的空行补回坐标后交给宿主。

思考块不计次数或耗时；
明确收到思考时显示“思考中”，空的流式消息只显示“处理中”。纯思考的段留 `✓ 思考` 摘要行，思考结束不消失，
避免回复上移。工具失败数不会被后续成功覆盖，助手的错误、中断和截断诊断始终保留。

宿主在助手 `contentContainer` 的直接子节点中，只把思考包在 MouseRegion。混合消息复用原生正文/错误节点，
独立渲染接收者继承原组件以保留 OSC133 消息跳转与鼠标布局，但只持有自己的 children 和布局缓存。原消息由
宿主失效更新；投影不能调用原生 invalidate 去重建共享子节点，也不复制思考展开状态。

宿主适配只有一个当前所有者，reload 先卸旧再装新；非 TUI 子会话不能安装或卸载主会话投影。借首个助手或
工具插入事件定位聊天容器，找到后立即卸掉发现钩子，不包装 `requestRender`。

只注册默认四工具的包装：注册 grep/find/ls 会改变启用工具集。成功结果未展开时只取长度与耗时，不清洗正文；
错误保留摘要，单工具展开保留原始正文和 edit diff。带背景的单行裁剪用根级 `clip`。
