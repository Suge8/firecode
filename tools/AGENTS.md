# tools：过程组与过程列表

| 文件 | 职责 |
| --- | --- |
| `index.ts` | 包装默认四工具的展示与执行耗时；TUI 会话安装分组，退出释放 |
| `grouping.ts` | 宿主适配：定位聊天容器，安装渲染/鼠标投影，分离全局展示与单工具正文 |
| `group-view.ts` | 从原组件顺序派生轮、过程组与折叠/展开投影 |
| `turn-summary.ts` `turn-clock.ts` | 摘要行渲染；时钟只把 `busy.ts` 的会话进行中事实投影到各轮（哪一轮开着、机器消息是否刚到），不记时长 |
| `round.ts` | 轮记录：歇下边沿把 `busy.ts` 给出的整段事实（时长、终态、均速）写成官方 CustomEntry（零行标记组件），摘要行落定时按能力从聊天树读它；持久化，resume 后仍有数 |
| `machine.ts` | 信封机器消息的一行投影（标题、首句、成败色、到达与失败事实），按信封来源各自解析，卡片与展开态共用 |
| `assistant-view.ts` | 思考/正文投影，封装宿主助手组件的内部结构，不重建 Markdown |
| `line.ts` `parts.ts` | 单工具行与着色片段；Master 复用纯渲染部分 |
| `timing.ts` | 真实工具执行耗时，结果渲染取走即释放 |

改分组前核对宿主 `ToolExecutionComponent`、`AssistantMessageComponent`、`Container` 和 TUI 动态引用。
原消息与聊天树不改写、不搬移；渲染与鼠标命中使用同一投影。两档展示直接读取 `getToolsExpanded()`，
不拦截快捷键。过程列表保留原生思考组件与其展开设置；单工具正文仍由宿主工具行持有，其他卡片保持原生行为。

折叠单位是**轮**：只有人类用户消息（不是整条由信封构成的用户消息）开启新的一轮，其左侧画橙色竖条。
轮内的过程节点是宿主组件：助手消息、工具行、CustomMessage，以及机器消息——空闲时 `deliver.ts` 走前门
`sendUserMessage`，模型侧是用户消息，UI 靠信封识别它，与忙时的 CustomMessage 同属过程，不切轮。段内还可能出现整行单色 `Text`——
宿主把 transcript 提示画成 warning、状态行画成 dim，颜色是它唯一给出的语义通道（只折入有工具或思考的段，连同前导
Spacer，warning 计入 `⚠ N`；无摘要行可依附时保持原样，避免为提示凭空造摘要行顶开回复）；错误、混色文本与其余节点
仍是段边界；宿主 CustomEntry 有段可依附时属于本轮（轮记录零行，折叠与展开都不占行；同一轮多条取后写的）。段尾回复是其后只剩提示与机器消息的最后一条助手消息。

折叠态一轮自上而下：用户消息 → 摘要行 → 最近 `replyLines` 条中间回复各一行灰色首句（更早的折成“+N 条”，
`replyLines=0` 不显示这两类；左边距与宿主正文同为 1 列）→ 最后一条回复全文。摘要行运行中是 `flame(1)` 与当前动作，无计数、不跳计时——实时状态与计时只在编辑器上边框一处。当前动作只说正在发生的事，只有三种：有工具在跑是动作词 + 简短目标（如“操作 $ bun test”）；没有工具在跑时，助手流式出正文是“回复中”，其余（等首字、思考、工具刚完成等下一次请求）是“思考中”；指挥官自己歇着只在等子代理时没有当前动作，只留火苗。窄屏先裁目标、再裁提示原文；
Master 落定类事件（带“耗时：本次运行”，运行中首次出现）到达时用事件标题（如“fix-auth 已返回”“fix-auth 审查通过（2 轮）”，成败色同 ↳ 行）替换当前动作约 2.5 秒；会话歇下后经 `settleMark` 冷却成
灰色“✓ 耗时 · 均速”，三者都来自这一段的轮记录（整段会话进行中的时长，含等待子代理；记录落在这一段最后一轮，同段更早的轮——等待期间补的话——只有 ✓），终态 aborted/error 画红 ✗ 并写“已中断”/“请求失败”且不带均速；冷却动画以记录时间戳为起点。进行中的轮与有轮记录的轮一律有摘要行，纯文字轮也是：从开始到歇下这一行一直在原位（歇下边沿与轮记录写入同一节拍），回复不跳。工具失败是模型的工作过程，不计数、不影响标记，细节在展开态每行自己标红；落定后这一轮有子代理失败（Master 事件带“错误：”分节——生产端把子代理失败、审查停止、审查未完成都写成它，被中断不算——按名字去重）追加红色“N 个子代理失败”（运行中失败行常驻在子代理活动列表，不重复），首条宿主提示追加“⚠ 原文”（多条只取首条）；窄屏先裁原文、再丢记录、最后丢提示原文，失败数保留。重载中途的那一段没有记录，只有 ✓。动效只经 `flame.ts` 的 `onFrame`：
投影发现有活的摘要或落定过渡才订阅，静止即取消。点击某轮摘要翻转这一轮（状态以该轮用户消息为键），它只是相对全局档位的覆盖：全局折叠时点开，全局展开时折起；ctrl+o 切全局档位时清空所有覆盖并复位被点开的原生卡片，所以它永远是“全部展开/全部折叠”；
展开态摘要不变，按时间顺序列出工具行、中间回复和机器消息一行“↳ 标题 · 时长 首句”，与上一个工具行或正文之间空一行，连续的 ↳ 行紧挨。标题与成败色由信封来源各自决定：Master 事件标题取正文第一行原样（“<名字> <结果词>”），带独占一行的“错误：”分节（不论排在第几个分节，此时首句取错误原文）或审查未通过/未完成/停止时为红，落定类带本次运行时长；review 结果卡标题取卡标题，未通过/未完成/顾问终止为红，首句取首条发现标题，否则原因，否则第一句非模型名的正文；观察员只写“观察员 + 建议首句”，时点标记留在完整卡里。机器消息（信封用户消息与内容为信封的 CustomMessage，含 review 结果卡）一律一行，点击该行切换完整正文（用户消息）或原生卡片（CustomMessage），交互与单工具行一致；全局展开不平铺它们，所以包装了 CustomMessage 的 `setExpanded`（只忽略机器消息）。

摘要行不铺工具背景色；摘要行只承担运行状态、耗时入口与异常提醒，没有按类计数与展开符号。一行预览的首句（机器消息行、中间回复、Master 事件卡与输入框展示标题共用根级 `format.ts` 的 `firstSentence`）是纯文本：跳过标题、围栏、表格行、分隔线与空行（只有标题时才用标题文字），剥掉引用符、列表符与序号，去掉行内 Markdown 标记；缩写（e.g.、vs. 等）与不后接空白的点不算句末；以冒号结尾则并入下一有效行的首句。宿主在用户消息（含空闲送达的信封）与提示前先插一个 Spacer，它跟着后面的节点走：后者属于本段，它就属于本段，否则一轮会被切成多段。当前动作词与目标由工具行的
`actionWord` / `actionTarget` 能力提供，按能力而非类身份选择，避免扩展多次加载产生的 ToolLine 副本不相等；未提供该能力的静态
工具使用通用参数摘要。内置四工具的动作词与目标格式唯一来源是 `actions.ts`（工具行与 Master 活动列表共用）；bash 目标省掉“cd 到当前工作目录 &&”前缀（含引号、`~`、尾斜杠写法），cd 到别处保留。单工具详情的鼠标事件按裁掉的空行补回坐标后交给宿主。

思考块不计次数或耗时。纯思考的段留 `✓` 摘要行，思考结束不消失，避免回复上移。助手的错误、中断和截断诊断始终保留。

宿主在助手 `contentContainer` 的直接子节点中，只把思考包在 MouseRegion。混合消息复用原生正文/错误节点，
独立渲染接收者继承原组件以保留 OSC133 消息跳转与鼠标布局，但只持有自己的 children 和布局缓存。原消息由
宿主失效更新；投影不能调用原生 invalidate 去重建共享子节点，也不复制思考展开状态。

宿主适配只有一个当前所有者，reload 先卸旧再装新；非 TUI 子会话不能安装或卸载主会话投影。借首个助手或
工具插入事件定位聊天容器，找到后立即卸掉发现钩子，不包装 `requestRender`。

只注册默认四工具的包装：注册 grep/find/ls 会改变启用工具集。成功结果未展开时只取长度与耗时，不清洗正文；
错误保留摘要，单工具展开保留原始正文和 edit diff。带背景的单行裁剪用根级 `clip`。
