# watcher：观察员

主会话每个 turn 结束后异步评估增量，要么沉默，要么投出一条建议。独立于 Master 与 fire-review 注册，关掉
不影响其余；观察会话与审查会话是 `isolated` 的，不加载 FireCode；Worker 子会话只注册 checkout 守卫，也不带观察员。

## 观察会话

只经根级 `spawn.ts` 创建：memory 持久化（观察过程不落盘、无 checkpoint）、只读工具
read/grep/find/ls、系统提示整体替换、注入 contextFiles、`isolated`（不加载用户的扩展、技能与模板：第三方扩展会在观察会话里产生外部副作用，技能表白占上下文；FireCode 自己也不注册进去）。池由 Master、观察员与审查共用（根 `index.ts` 只建一个），Master 关闭只释放落盘的子代理会话，不动观察会话。`prompts/watch.{zh,en}.md` 的四段（角色克制、关注面、输出契约、证据纪律）缺一不可。

`advise` 是注入观察会话的唯一自定义工具，也是观察员唯一的输出通道：正文文字不会被任何人看到。它只收
`note` 一个参数——评估结果只有说与不说两态，没有档位。同一次评估的第二次调用当场拒绝，多余的问题留到
下一次。评估一轮结束时宿主不会让 `prompt` 抛出供应商错误，只把它记在最后一条助手消息上：观察会话在没有建议时读到 `stopReason: "error"` 就抛出原因，走下面的停用路径，不装作还在工作；已记下建议时不因收尾那一问失败而丢掉它。观察会话里的扩展出错（`onExtensionError`）只提示，不停用。

## 触发与重置

`turn_end` 把渲染好的增量推进待评估缓冲，评估在后台跑。评估期间到达的回合合并进下一批——只有缓冲，
没有积压队列，落后时天然跳到最新。喂给会话的增量始终是 append-only 的新内容，已评估过的回合留在前缀里
不重发，前缀缓存因此有效。增量内容与 `minimal` / `full` 的区别见 `transcript.ts` 头注释。渲染直接吃宿主的 `TurnEndEvent` 类型，不得改回
手写结构型：字段名对不上时增量会静默变空。

fire-review 活跃期（读 `watchBusy` 视图的 `review`）零评估，增量留到审查结束合并处理。主会话
compaction、会话切换或观察会话自身上下文超过阈值时，丢弃观察会话与未评估增量，从当前尾部重新入场，
不回放历史。重新入场会更换 runtime owner：在途评估看的是旧现场，它的建议被丢弃，它的故障也不会关掉观察员；
迟到创建的观察会话立即释放。

## 投递

发言只有一条路径，与指挥官事件同构：经根级 `deliver.ts` 统一投递（机制见其头注释）；Esc 打断后同样
照发。发言不阻塞评估循环：同一时刻只有一条未送达的发言，新建议、主会话压缩或会话失效时用 `deliver` 的 signal 中止上一条，它不再补投（过时建议没有价值）；观察会话自身因上下文过长而重新入场不算失效。建议自带时点标记（「基于第 N 回合前的观察」），投递时主会话可能已经走远。进入模型上下文的正文包在
`<firecode_watcher>` 信封里，权衡声明位于信封末行。不分严重度档位：只投卡不唤醒的档位让纠偏滞后到用户下次开口，只给人看的档位没有模型消费者；代价是每次开口都可能唤起一个回合（含 Esc 之后），接受。
一条发言投递失败只丢弃这一条并提示，观察员照常工作——建议过时后重投没有价值。

## 配置

`watcher` 节的字段与默认值见 `config.ts`，模型必须显式配置。`features.watcher` 开关本身写错（字符串
`"false"` 会因 `!== false` 静默启用）也算配置问题。模型由子会话池解析，必须能在内置 provider 或 models.json 解析——扩展注册的 provider 在
子会话里不可解析，解析失败时报错引导改用内置 provider 模型。

裸 `/fire-watch` 翻转当前会话，不写回配置。启用时通过 `setStatus` 发布“观察员”，关闭或故障停用时清除；
标签只表示功能已启用，审查期间仍按规则静默。模型与思考档保留在配置中，输入框边框不重复展示。

建议卡收起时显示标题与正文首行并按宽裁剪，展开时显示完整正文。
