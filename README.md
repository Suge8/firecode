# FireCode

FireCode 是一个模块化 Pi Package，提供终端状态与工具渲染、会话预设、`/fire-review` 对抗审查、`/fire-master` 进程内子代理委派和 `/fire-watch` 观察员。指挥官与观察员的新会话状态由配置决定，裸命令只翻转当前会话；各模块由功能开关独立注册，关闭任一模块不会改变其余模块。

## 安装

```bash
pi install git:github.com/Suge8/firecode@v0.6.1
```

也可在本地仓库中直接试用：

```bash
pi -e .
```

Pi Package 拥有与 Pi 相同的本机权限；安装前应审阅源码。

## 配置

运行配置不随包分发。将公开模板复制到 Pi Agent 目录后按需启用功能，再重启 Pi：

```bash
agent_dir="${PI_CODING_AGENT_DIR:-$HOME/.pi/agent}"
mkdir -p "$agent_dir/extensions/firecode"
curl -fsSL https://raw.githubusercontent.com/Suge8/firecode/v0.6.1/config.example.jsonc \
  -o "$agent_dir/extensions/firecode/config.jsonc"
```

公开模板提供维护者当前的完整推荐配置：除 Bark 外功能全开，Master 在新会话自动激活，Watcher 不自动激活。Watcher 激活后每个主会话回合调用模型，OpenAI priority 会按供应商规则加价；复制前应确认列出的模型均已认证并接受额外费用。配置里指定模型一律写 `"provider/model/thinking"`；审查与观察员的模型必须显式写入运行配置，否则对应功能拒绝启动。缺少运行配置时，FireCode 会关闭可选功能并在会话启动时警告；配置模板本身不会被运行时读取。

## 终端展示与额度查询

会话启动横幅按终端宽度分三档（像素火焰配字标 / 小号字标 / 一行），副标题是 `pi 版本 · 工作目录`，放不下时（如 40 列的一行档）只留目录、从开头按整段省略（如 `…/tmp/fc-repo`）。
审查结果卡标题前用单色字形，颜色只表达结论：`✓` 通过（绿），`✗` 未通过或终止（红），`◌` 未完成（红），`‖` 已取消（灰），开始与顾问指引用审查的金色点阵 `⠿`。

状态嵌进输入框的上下边框，没有独立底栏。上边框左侧在会话进行时显示火苗、“处理中”或“等待 N 个子代理”与计时，主会话审查进行时
追加金色转圈点与审查进度，如 `⠹ 审查 第2轮 1/3 · 1 阻断`（窄屏依次省掉阻断数、票数，“审查 第N轮”留到最后），这是界面上唯一的审查进度；主会话审查也算会话进行中，计时照常走、审查时长记进这一轮；歇下那一刻直接显示 `✓ 耗时 · 均速`（中断或请求失败是红 `✗ 已中断` / `✗ 请求失败`）并留到下一轮开始；右侧是观察员与“指挥官”（表示功能已开启，不表示已做网络健康检测）。
下边框左侧是会话标题，右侧是生效中的预设名（只在预设改了工具集或附加指令时显示，只换模型的预设看模型名即可）、模型与思考档、Fast（开启时）、上下文占用与容量（如 `/1M`、`/200k`）。未重命名时标题取首条用户文本的完整首句，
尚未输入时显示“新会话”；这不会修改正式会话名。窄屏依次省容量、让出预设名、裁标题（留够认出会话的几个字）、裁模型名，完整保留上下文百分比与 Fast。
审查等模型结论时输入区收起成一行“审查进行中 · esc 取消”。Pi 的缓存告警保留。边框示意：

```text
─ ⣾⣿⣷ 处理中 1m3s · ⠹ 审查 第2轮 1/3 · 1 阻断 ──────────── 观察员 指挥官 ─
 输入区
─ 优化插件状态栏和工具展示 ───────────── gpt-6-astra/medium Fast · 42.3%/200k ─
```

极致模式以一次人类输入为单位折叠：用户消息（左侧橙色竖条）下方是一行摘要，思考、所有工具调用（含图片结果与子代理动作）、
子代理结果与观察员发言等机器消息、中途说的话都折进去——上一轮还没歇下时你补的话（steer 或等子代理时的追加）也属于这一轮，折叠时与普通用户消息一样带竖条显示全文，只是不再另起一轮；Pi 的单行提示（缓存重计费、丢弃思考块、压缩计费）与状态行
也折进有工具或思考的过程组。摘要下方依次是最近几条中间回复的首句（条数由 `tools.replyLines`
配置，默认 3，更早的显示为 `+N 条`，0 表示不显示；首句跳过标题、列表符、表格这类 Markdown 结构，取第一句有正文的话）和最后一条回复全文；错误消息照常显示。
摘要行运行中是火苗与当前动作：工具在跑时是动作词加简短目标（如 `操作 $ bun test`，cd 到当前目录的前缀省掉），模型在想是“思考中”，在出正文是“回复中”，窄屏先裁目标；一轮从开始到歇下这一行一直在原位，回复不跳。子代理结果到达时短暂显示事件标题（如“fix-auth 已返回”“fix-auth 审查通过（2 轮）”，失败为红）；指挥官只在等子代理时只有火苗。实时计时只在输入框上边框一处，自你这次输入起连续累计，中途补话与子代理结果唤醒都不重置。会话歇下（含等完子代理）后定格为灰色 `✓ 耗时 · 均速`，例如 `✓ 2m18s · 42 tps`，耗时达到一小时显示为 `1h`、`4h13m37s` 等形式；按 Esc 中断或请求失败时是红色 `✗ 已中断 · 耗时` / `✗ 请求失败 · 耗时`，不带均速。均速只计算模型请求耗时（含首字与网络等待）和输出 token（可能含思考），等子代理与工具执行不算；一轮里有请求失败、中断或压缩失败就整轮不显示均速。只有文字回复的轮同样有这一行。工具调用失败不计数、不影响标记（展开后每行自己标红）；这一轮有子代理失败时追加红色 `N 个子代理失败`，有 Pi 的宿主提示（缓存重计费等，多条取首条）时追加 `⚠ 提示原文`，窄屏先裁原文、再丢耗时、最后丢提示原文。这条事后记录保存在会话里（不发送给模型），resume 后仍然显示。
点击某一轮的摘要只展开这一轮；按工具展开快捷键（默认 `Ctrl+O`）展开所有轮，按时间顺序列出工具、
中间回复和 `↳ 标题 · 时长 首句` 机器消息行（如 `↳ fix-auth 已返回 · 8m 刷新改为单飞。`、`↳ 审查未通过 刷新竞态未修`、`↳ 观察员 建议原文`；失败、审查未通过/未完成/停止为红；点击该行看完整内容），再按回到折叠。思考和单工具正文继续使用原生查看方式。
只有思考没有工具的段，摘要行同样是 `✓`。

指挥官模式下，输入框上方逐行列出子代理：需要处理的置顶——红 `✗` 失败（含审查停止、审查未完成）与黄 `‖ 被中断`
留到指挥官 ack 或 kill，黄 `◌` 加动作后的 `· N 分钟无输出` 表示在跑的子代理 5 分钟没有任何输出、有输出立即恢复；然后是在跑与审查中的行，
再是 `✓ N 个已完成`（kill 后才去掉）与 `N 个空闲`（resume 后池里还在的、已发落的）。在跑的行最多显示 `max(4, 终端高度/6)` 行，超出折成 `… +N 个在跑`；
点它展开全部、点“… 收起”折回，点 `✓ N 个已完成` 列出名字、结果首句与本次运行耗时，点 `N 个空闲` 列出空闲的子代理，再点收起；展开在你下一次发消息时自动收起，`Ctrl+O` 不展开活动列表。
窄屏整表一起省掉角色，动作文字按剩余宽度截短。

`/quota` 查询已在 Pi 中 OAuth 登录的 Codex、Claude 订阅剩余额度，并展示接口提供的 Fable 周额度。
结果带查询时间，不打断当前工作、不发送给模型；未登录或查询失败会明确显示。查询没有后台刷新或磁盘缓存，
结果是供应商返回的快照，不保证供应商零延迟。Fable 与总体周额度共享约束，不是额外额度。
`features.stats` 控制 `/quota` 和本地用量统计 `/tokens`。

## Claude 订阅

`features.claudeSub` 让 Claude 订阅（Anthropic OAuth）会话的请求带上 Claude Code 归因。Anthropic 换发订阅令牌时会立即
作废旧令牌，此刻仍在途的请求以 401 失败；FireCode 用新令牌自动重试一次，主会话底部提示「Claude 令牌刚换发，已自动重试」，
子代理静默续跑，不触发 fallback。重试仍被拒说明登录确已失效，照常报错，需要重新 `/login`。API key 的 401 不重试。

## 开发

需要 [Bun](https://bun.sh/) 和一个 pi-mono checkout。开发版 `pi` 在 `PATH` 中时，测试会自动定位它；否则设置 `PI_PACKAGES_DIR` 为 pi-mono 的 `packages/` 目录。

```bash
bun test
```

模块边界、状态机约束和领域术语见 `AGENTS.md`、各模块的 `AGENTS.md` 与术语表 `WORDS.md`。
